# 提案大綱：智慧職缺推薦系統

---

## 一、專案摘要

針對求職平台上約 100 萬筆職缺，設計並實作一套智慧推薦演算法，根據使用者的搜尋意圖與歷史行為，即時推薦最相關的 Top 10 職缺。系統結合 LLM 語意理解、高速 SQL 篩選引擎、以及個人化排序策略，兼顧匿名與登入用戶的推薦需求。

---

## 二、問題定義

- **痛點**：傳統關鍵字搜尋僅能做精確比對，無法理解口語化查詢、縮寫、同義詞；排序僅依發布時間或簡單權重，缺乏個人化能力
- **挑戰**：
  - 百萬級職缺的即時篩選效能
  - 自然語言查詢的語意理解（縮寫展開、拼字修正、薪資意圖提取）
  - 匿名 vs 登入用戶的差異化推薦策略
  - 冷啟動問題（新用戶歷史不足）

---

## 三、解決方案概述

### 三階段 Pipeline 架構

```
使用者查詢 (自然語言)
       ↓
  [Stage 1] 語意解析 — LLM 標籤提取
       ↓
  [Stage 2] 智慧檢索 — 語意擴展 + SQL 篩選
       ↓
  [Stage 3] 個人化排序 — 行為特徵匹配 + 熱門度混合
       ↓
  Top 10 推薦結果
```

---

## 四、核心技術模組

### 4.1 語意解析（querytoRequirement）

| 技術 | 說明 |
|------|------|
| 縮寫展開 | 規則式替換（13 組對照：pt→兼職、fe→前端工程師 等） |
| LLM 解析 | AWS Bedrock Claude — 將口語查詢轉為結構化標籤 |
| 後處理 | 城市名正規化、薪資格式統一 |
| 容錯機制 | LLM 失敗重試 3 次，最終 fallback 至規則式分詞 |

### 4.2 智慧檢索（grabFromDatabase）

| 技術 | 說明 |
|------|------|
| 語意擴展 | 透過職務對照表 CodeAlike 欄位展開同義職稱 |
| 查詢引擎 | DuckDB（in-process SQL，百萬列 CSV 毫秒級過濾） |
| 熱門度附加 | LEFT JOIN 預計算的時間衰退熱門分數 |
| 多維篩選 | 支援城市、薪資、職缺屬性、職務類別等多重條件 |

### 4.3 個人化排序（ranking）

| 用戶類型 | 排序策略 |
|----------|----------|
| 匿名用戶 | 依時間衰退熱門分數排序 |
| 冷啟動用戶（事件 < 3） | 退回熱門排序 |
| 一般登入用戶 | `final = personal_score × 0.7 + popularity × 0.3` |

**個人化評分公式：**
```
personal_score = 地點匹配 × 0.4 + 職類匹配 × 0.4 + 薪資匹配 × 0.2
```

### 5.2 衍生資料（離線 ETL）

| 衍生表 | 用途 | 計算方式 |
|--------|------|----------|
| 瀏覽次數.csv | 職缺熱門度 | `score = Σ e^(-0.1·Δt) × weight`（apply=3, view=1） |
| userBehaviorFeature.csv | 用戶偏好特徵 | Top-3 偏好城市/職類 + 薪資基準 |

## 六、技術架構

### 6.1 技術選型

| 元件 | 技術 | 理由 |
|------|------|------|
| LLM | AWS Bedrock (Claude 3.5 Sonnet) | Structured output、低延遲、免部署 |
| 查詢引擎 | DuckDB 1.3.0 | In-process、百萬列毫秒級、零基礎建設 |
| 語意擴展 | 規則式（職務對照表） | 快速實作、確定性高、不依賴外部服務 |
| API 框架 | FastAPI + Uvicorn | 高效能 async、自動 OpenAPI 文件 |
| 圖譜（可選） | networkx | 協同過濾、可切換開關、已實作備用 |

### 6.2 部署架構

```
[Client] → HTTP POST → [EC2 t3.large / FastAPI] → [AWS Bedrock]
                              ↓
                    [DuckDB (in-process)] ← 職缺.csv (~1M)
                              ↓
                    Top 10 JSON Response
```

- 部署平台：AWS EC2（t3.large, 8GB RAM）
- API Endpoint：`POST /recommend`
- 自動化部署：CloudFormation + PowerShell 腳本

## 七、效能指標

| 指標 | 數值 |
|------|------|
| Stage 1（語意解析） | 1–3 秒（受 LLM 延遲影響） |
| Stage 2（資料檢索） | 50–200 毫秒 |
| Stage 3（排序） | < 10 毫秒 |
| 端到端延遲 | 1–3.5 秒 |
| LLM Fallback 延遲 | < 10 毫秒 |

---

## 八、創新亮點

1. **LLM 語意理解 + 規則式容錯**：結合大型語言模型的理解能力與確定性規則的可靠性
2. **時間衰退熱門度**：避免舊職缺霸榜，反映真實市場熱度
3. **雙軌排序架構**：特徵匹配（預設）+ 圖譜協同過濾（可選），透過環境變數一鍵切換
4. **冷啟動優雅降級**：新用戶自動退回熱門排序，無硬失敗
5. **百萬級即時查詢**：DuckDB in-process 引擎無需額外基礎建設即達毫秒級
