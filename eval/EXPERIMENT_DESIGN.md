## 要回答的問題

> 移除生成式 AI 後，NDCG@10 是否顯著退化？

這是命題「主題切合度」（20%）的驗證方式，由評審實際執行本框架判定。

---

## 標準答案從哪來

主辦方的標註集不對參賽者開放，因此用**使用者的真實行為**當答案 —— 這也是命題的定義：

| 等級 | 定義 |
|---|---|
| 2 | 搜尋後投遞履歷 |
| 1 | 搜尋後點閱職缺 |
| 0 | 無互動 |

*（不採用 LLM 判斷相關性：用 LLM 評測一個用 LLM 的系統，存在同源偏誤。）*

---

## 時序切分

主辦方**未公告官方切分**（命題說工作坊會提供，實際只公告了資料範圍），故自訂如下：

```
06-01 ~ 06-05  │  06-06  │  06-07
├─── 訓練期 ───┤          │
                ├─考題────┤
                ├──標註觀察窗口──┤
```

**06-07 只當答案、不出題。** 標註需要「往後看」使用者的行為；若拿最後一天出題，該日晚上的搜尋沒有後續資料可觀察，會被誤標成「沒有正確答案」，系統性壓低所有組的分數。

---

## 四個關鍵設計決策

**1. 歸因窗口 = `[搜尋時間, min(+30分, 下一次搜尋)]`，下限 2 分鐘**
下一次搜尋當切點，避免把後續搜尋的點擊算給這一筆；設下限是因為使用者連續改關鍵字時（可能間隔數秒），窗口會塌縮成 0，前幾筆全被誤判成無答案。

**2. 不把答案限制在 `empStr` 裡** ⭐
`empStr` 是既有系統當時顯示的清單。若答案只能來自它，你們就算找出更適合、但舊系統沒顯示過的職缺也會被判錯 —— **結構上不可能超越舊系統**。
實證：標註的相關職缺只有 **16.0%** 出現在舊系統前 20 名。若加這個限制，會丟掉 84% 的答案。
代價是引入雜訊（使用者可能從別的路徑點進職缺），已列為已知限制。

**3. 只取登入使用者**
`talentNo = 0` 無法歸因行為，納入只會產生全零標註。母體覆蓋率 73%。

**4. 加一組「完全不排序」對照**
命題只要求「有圖譜 vs 無圖譜」。加下界對照組，是為了排除「兩個排序策略其實都無效」這種兩兩比較看不出來的情況。實測證實熱門度排序是有效的（3.0 倍）。

## 防洩漏

| 風險 | 措施 |
|---|---|
| 熱門度包含測試日的點擊 | 只用 06-01~06-05 事件重建（`瀏覽次數_train.csv`） |
| **時間衰退基準日洩漏未來** | 參考日設為訓練期最後一刻，非資料檔最後一日 ⭐ |
| 圖譜使用測試期職缺 | 限用 `職缺最後修改時間 < 06-06`（967,377 筆，79.4%） |
| 用 `talentNo` 個人化高估表現 | 評測時一律設 0，與官方 API 合約一致 |

⭐ 這條容易漏。衰退公式 `Δt = 參考日 − 事件時間`，若參考日取自資料檔最新事件（06-07），就已隱含「知道資料延伸到 06-07」的未來資訊。不會報錯，但分數會虛高。

## 框架自身怎麼驗證

**指標**：`metrics.py` 內含 9 項手算斷言（完美排序 = 1.0、順序顛倒的精確值、截斷點生效、無答案的題目被排除…）。跑 `python eval/metrics.py` 可重驗。指標算錯的話，後面所有數字都是廢的。

**環境**：跑任何 LLM 組之前先實際打一次 Bedrock。因為 `querytoRequirement()` 失敗時會**靜默**退回規則式分詞 —— 若評測時發生，「有 LLM」與「無 LLM」會跑出一模一樣的數字，等於自證「AI 沒用」。探測失敗則拒跑並報告原因。此機制實際抓到了環境設定錯誤。

## 設定怎麼切換

不改受測系統原始碼，執行期替換模組變數：

```python
R.VIEWS_PATH      = 訓練期熱門度表        # 防洩漏
R.semantic_expand = 原函式 / 恆等函式      # 語意擴展開關
K.GRAPH_FOR_ANONYMOUS = True / False      # 圖譜開關
parse             = LLM / 規則解析器       # 生成式 AI 開關
```

隊友可以繼續改 `src/`，不會跟評測衝突。「關閉 LLM」直接呼叫系統既有的 fallback 元件，確保模擬的是真實降級行為。

## 已知弱點

| 弱點 | 說明 |
|---|---|
| 行為標註有雜訊 | 使用者可能從首頁、收藏點進職缺，被誤歸因 |
| `label = 0` ≠ 不相關 | 受曝光偏差影響，已量化為 16.0% |
| 測試日是週六 | 流量僅週一的 61%，職類分布不同 |
| 偏向登入使用者 | 匿名搜尋全排除 |
| 未做顯著性檢定 | 目前只存彙總指標，未存逐題分數 |
| 召回診斷樣本小 | 27.9% 係在 40 筆上量測，非完整 500 筆 |

## 主要參數

| 參數 | 值 |
|---|---|
| 訓練期 / 考題日 / 標註窗口 | `06-01~06-05` / `06-06` / `06-06~06-07` |
| 歸因窗口 | 30 分鐘上限、120 秒下限 |
| 測試集大小 | 500（自 40,000 候選中篩出，有效率 56.7%） |
| Random seed | 42（相同 seed 下測試集逐位元一致） |
| 應徵 / 瀏覽權重、衰退 λ | 3 / 1、0.1（沿用系統既有設計） |
| NDCG gain 慣例 | linear（對齊主辦方指定的 `pytrec_eval`） |
