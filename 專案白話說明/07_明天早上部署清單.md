### 關於 Bug 2

`sonnet-4-6` 回傳的是乾淨 JSON，**所以目前不會發作**。但這是單一模型的行為特性，不是保證 —— 實測 `haiku-4-5` 與 `sonnet-4-5` 都會包 markdown fence。

新增的 `_extract_json_array()` 是防禦性修正：剝掉 fence、並取最外層 `[...]`，讓任何模型都能安全解析。**這個 bug 危險的地方在於它不會報錯** —— 系統照常回傳結果，只是 LLM 從未真正參與。

```bash

python3.11 -c "
import boto3, json

                     'messages':[{'role':'user','content':'hi'}]}))
print('OK', json.loads(r['body'].read())['content'][0]['text'])
"
```

| 錯誤訊息 | 原因 | 處置 |
|---------|------|------|
| `ResourceNotFoundException ... end of its life` | 模型 ID 還是舊的 | `.env` 的 `BEDROCK_MODEL_ID` 沒生效，確認有重啟服務 |
| `UnrecognizedClientException` / `security token ... invalid` | 憑證過期 | 重新取得臨時憑證（黑客松憑證通常只有幾小時效期） |
| `AccessDeniedException` | 該帳號沒開這個模型的權限 | 改用 `us.anthropic.claude-sonnet-4-5-20250929-v1:0`（實測也可用） |
| `InvalidRegionError` | region 欄位被填錯 | 確認 `AWS_DEFAULT_REGION=us-west-2`，不要把 token 貼進 region |

## 另外兩個建議（有時間再做）

### A. 檢索加 `LIMIT`（一行，高 CP 值）

實測有查詢會撈回 **1,149,322 筆候選**（幾乎整個資料庫），記憶體峰值 6.8 GB。
伺服器是 t3.large 只有 8 GB，**評審打到這種查詢可能逾時或 OOM**。

`src/retriever.py` 的 SQL 加上：

```sql
ORDER BY COALESCE(p.score, 0.0) DESC
LIMIT 5000
```

最終只取前 10 名，撈一百萬筆進來排序沒有意義。同時改善延遲、記憶體、穩定性。

### B. 空結果的保底

目前只要撈到 0 筆就直接回空陣列。建議：**撈到 0 筆時放寬條件重撈一次**（丟掉職稱關鍵字，保留城市／薪資／職務類別）。

命題 FAQ 說「沒結果回 `result: []`」格式上合法，但**每一筆空結果 = 那題所有指標都 0 分**。
