## 一、系統相關

### Pipeline（流水線／管線）
把一件複雜的事拆成幾個固定順序的步驟，一關接一關。
我們的是三關：**解析 → 檢索 → 排序**。
好處：每一關可以獨立測試、獨立優化、獨立換掉。

### LLM（大型語言模型）
就是 ChatGPT / Claude 這類會讀寫人話的 AI。
我們用它做**一件很具體的事**：把「台北後端 pt工作」翻譯成結構化標籤。

### AWS Bedrock
亞馬遜雲端上的「AI 模型商店」。不用自己架 GPU 伺服器，
打個 API 就能用 Claude、Llama 等模型。我們用的是 **Claude 3.5 Sonnet**。

### Prompt / System Prompt
給 AI 的指令。System Prompt 是「角色設定 + 規則」，
我們的 system prompt 寫在 `src/query_parser.py` 開頭，
內容大意是「你是職缺搜尋的標籤提取器，只准回傳 JSON 陣列，地點要加市/縣，薪資要寫成 薪資>=數字」。

### DuckDB
一個**不用架伺服器**的資料庫（術語叫 in-process，跟程式跑在同一個行程裡）。
最強的地方：**可以直接對 CSV 檔案下 SQL**，100 萬列也是毫秒級。
類比：MySQL 像餐廳（要先開店、請人、進貨），DuckDB 像微波爐（插電就能用）。

### FastAPI / Uvicorn
Python 寫網站 API 的工具組。FastAPI 負責定義「有哪些網址、收什麼資料」，
Uvicorn 是實際跑起來的伺服器。附贈自動產生的互動文件頁面 `/docs`。

### EC2
AWS 的雲端虛擬機器，就是「租一台電腦放在網路上」。
我們租的是 t3.large：2 核心 CPU、8GB 記憶體。

### CloudFormation
AWS 的「機器設定寫成檔案」工具。
把要開什麼機器、開哪些防火牆規則寫成 yaml，一個指令就全部建好，也能一次全部刪掉。

### Docker / Dockerfile
把程式和它需要的環境打包成一個「箱子」，搬到哪台機器都能跑。
`Dockerfile` 就是打包配方。

### AWS Kiro
AWS 的 AI 開發環境（IDE），主打「規格驅動開發」——
先寫需求 → 生設計 → 拆任務 → 才寫程式。**本次比賽用了可以加 5%。**

## 二、演算法相關

### 語意擴展 / 同義詞擴展（Semantic Expansion）
使用者打「Backend」，但職缺寫「後端工程師」，硬比對就漏掉了。
我們用主辦方 `職務對照表.csv` 的 **CodeAlike（相似職稱）** 欄位，
把一個關鍵字擴展成一串相關寫法，一起去比對。

### 時間衰退（Time Decay）
「越舊的事情越不重要」的數學寫法：

```
權重 = e^(-λ × 過了幾天)      我們用 λ = 0.1
```

λ=0.1 大約表示 **7 天前的互動只剩一半價值**。
目的：避免舊職缺靠累積的瀏覽次數永遠霸榜。

### 冷啟動（Cold Start）
新使用者／新職缺沒有歷史資料，系統不知道該推什麼。
我們的處理：行為少於 3 次就標記為冷啟動，**直接退回熱門度排序**，不硬猜。
資料顯示 21.8% 的使用者屬於這一類。

### 協同過濾（Collaborative Filtering）
「跟你口味相似的人還喜歡什麼」的推薦法。Netflix、蝦皮都在用。
我們的圖譜版本走兩跳：**你 → 你看過的職缺 → 也看過的人 → 他們還看了什麼**。

### 圖譜 / Graph（節點 node、邊 edge）
把資料畫成「點跟線」。
我們的圖：**點 = 使用者 或 職缺；線 = 某人看過／投過某職缺**，
線上有權重（投履歷 = 3、瀏覽 = 1）。共 44.1 萬個點、320 萬條線。

### Degree（度數）／加權入度
一個點連了幾條線。
「加權入度」= 指向某個職缺的所有線的權重總和 → 等於「這個職缺被多少人、多認真地看過」。

### Ablation（消融實驗）
「拿掉某個零件，看效果掉多少」的實驗方法。
命題明確要求交出「**有圖譜 vs 無圖譜**」的雙重指標對照，
用來證明生成式 AI 不是裝飾品。⚠️ 我們目前**還沒有實測數字**，見風險文件。

### 正規化（Normalisation）
把不同尺度的分數壓到同一個範圍（通常 0～1）才能相加。
例：熱門分數可能是 0～5000，個人分數是 0～1，
不先除以最高分就相加的話，熱門分數會完全蓋過個人分數。

## 三、評分指標（評審一定會提）

假設某次搜尋的正確答案有 5 筆，我們回傳 10 筆：

### NDCG@10
**「前 10 名排得好不好」**，滿分 1.0。
相關的職缺排越前面分數越高（第 1 名的貢獻遠大於第 10 名）。
名字全稱是 Normalized Discounted Cumulative Gain，不用背。

### Hit@1 / Top-1 relevance
**「第一名有沒有猜對」**，對 = 1，錯 = 0。使用者第一眼看到的東西。

### Hit@10 / Precision@10
**「前 10 名裡有幾個是對的」**，除以 10。
不足 10 筆也還是除以 10。

### MRR（Mean Reciprocal Rank）
**「第一個正確答案排在多前面」**。
排第 1 → 1 分，排第 2 → 0.5 分，排第 4 → 0.25 分，所有查詢平均。

### 分級相關性（Graded Relevance）
命題給的答案不是「對／錯」二選一，而是三級：

| 等級 | 意思 |
|------|------|
| 0 | 沒互動 |
| 1 | 點進去看了但沒投 |
| 2 | 點了而且投履歷 |

⚠️ 命題特別警告：**0 不等於不相關**，可能只是排太後面沒被看到（這叫**曝光偏差 / position bias**）。

### 曝光偏差修正（IPS / Doubly Robust）
修正「排在前面的天生比較容易被點」這個偏差的統計方法。
命題說「鼓勵但非強制」，**我們沒有做**，README 要標註清楚。

## 四、工程細節

### 優雅降級（Graceful Degradation）
出事的時候不要整個死掉，退回一個比較笨但能用的模式。
我們有三層：AI 失敗 → 重試 3 次 → 退回規則式分詞；
圖譜失敗 → 退回特徵排序 → 再退回熱門度排序。

### 快取（Cache）
算過一次的東西存起來，下次直接拿。
我們有：CSV 讀進記憶體後不重讀、圖譜存成 pkl 檔（4-5 分鐘 → 5 秒）。

### 參數化 SQL（Parameterised Query）
把使用者輸入當「參數」丟給資料庫，而不是直接串成字串。
可以防止 SQL Injection 攻擊。我們的 retriever 有做。

### 環境變數 / `.env`
把金鑰、開關設定寫在程式外面的檔案，不進版控。
我們的開關：`GRAPH_FOR_SIGNED_IN_USER`、`GRAPH_FOR_ANONYMOUS_USER`（預設都是 false）。

### ETL
Extract（抽取）→ Transform（轉換）→ Load（載入）。
就是「把原始資料嚼過一遍變成好用的表」的統稱。
我們的 `genViewCount.py` 和 `userAnalysis.py` 就是 ETL 腳本。
