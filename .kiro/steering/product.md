# Product Overview

A job recommendation algorithm that returns the top 10 most relevant job listings for a given user search query.

## Core Goal

Given a user's search query (and optionally their login history), surface and rank the 10 best-matching job listings from ~1,000,000 job listings.

## Three-Stage Pipeline

```
User query (str)
     ↓
querytoRequirement()   — LLM semantic parsing → tags list
     ↓
grabFromDatabase()     — semantic expansion + DuckDB SQL filter + JOIN popularity score
     ↓
ranking()              — popularity-based (anonymous) or personalised (logged-in)
     ↓
Top 10 job listings
```

### Stage 1 — Semantic Analysis (`querytoRequirement`)
- Spell-check and abbreviation expansion (e.g. `pt` → 兼職, `ue` → 使用者體驗設計師)
- LLM outputs a structured tags list (e.g. `["後端工程師", "兼職", "台北市", "薪資>=35000"]`)
- Fallback to raw keyword search if LLM output fails schema validation

### Stage 2 — Retrieval (`grabFromDatabase`)
- Semantic expansion via `職務對照表.CodeAlike` (e.g. 軟體工程師 ↔ 軟體設計師)
- DuckDB SQL filter on `職缺.csv` (~1M rows) for speed
- JOIN `瀏覽次數.csv` to attach popularity score to each candidate result

### Stage 3 — Ranking (`ranking`)
- **Anonymous user** (`talentNo = 0`): rank purely by `瀏覽次數.score`
- **Logged-in user** (`talentNo ≠ 0`):
  - Look up `userBehaviorFeature.csv` for pre-computed preference features
  - **Cold-start** (`total_events < 3`): fall back to popularity ranking
  - **Normal**: `final_score = personal_score × 0.7 + popularity_score × 0.3`
    - `personal_score` = location match × 0.4 + category match × 0.4 + salary match × 0.2

## User Behaviour Data (Option 3 — dual-file, adopted)

Two derived tables are pre-generated by `userAnalysis.py`:

- **`userBehaviorFeature.csv`** — one row per authenticated user; fast lookup for `ranking()`
- **`userBehaviorEvents.csv`** — full event log; used for advanced analysis and future Graph RAG migration

Anonymous rows (`talentNo = 0`) are excluded from both tables.

## Target Users

Job seekers on a job platform. Users may be:
- **Anonymous** (`talentNo = 0`): no personalisation, popularity-based ranking only
- **Authenticated** (`talentNo ≠ 0`): personalised ranking based on view/apply history
  - **Cold-start**: fewer than 3 historical events → treated same as anonymous
