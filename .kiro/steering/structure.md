## Dataset Key Relationships

```
職缺.職缺編號  ──  主動應徵.empNo
職缺.職缺編號  ──  職缺瀏覽.employeeNo
職缺.職缺編號  ──  userSearchLog.empStr       (comma-separated)
職缺.廠商編號  ──  職缺瀏覽.organNo
userSearchLog.talentNo  ──  職缺瀏覽.talentNo  ──  主動應徵.talentNo
城市對照表.CodeNo  ──  userSearchLog.c0        (comma-separated)
職務對照表.CodeNo  ──  userSearchLog.d0        (comma-separated)

── Derived table joins ──
瀏覽次數.職缺編號           ──  職缺.職缺編號
userBehaviorFeature.talentNo ──  職缺瀏覽.talentNo / 主動應徵.talentNo
userBehaviorEvents.job_id    ──  職缺.職缺編號
job_skills_cache.職缺編號    ──  職缺.職缺編號
graph_cache (nodes)          ──  職缺.職缺編號, userBehaviorFeature.talentNo
```

## Derived Table Schemas

### `瀏覽次數.csv`
| Column | Type | Description |
|--------|------|-------------|
| `職缺編號` | int | Job listing primary key |
| `瀏覽次數` | int | Raw view count |
| `主動應徵次數` | int | Raw application count |
| `score` | float | Time-decayed popularity score: `Σ e^(-0.1·Δt) × weight` (apply=3, view=1) |

### `userBehaviorFeature.csv`
One row per authenticated user (`talentNo ≠ 0`). Used by `ranking()` for fast personalised scoring.

| Column | Type | Description |
|--------|------|-------------|
| `talentNo` | int | User primary key |
| `preferred_city_1/2/3` | str | Top 3 cities weighted by apply×3 + view×1 |
| `preferred_category_1/2/3` | str | Top 3 job mid-categories by same weighting |
| `salary_floor` | float | 25th percentile of applied jobs' 薪資下限; null if < 3 apply events |
| `total_events` | int | Total view + apply events (cold-start check) |
| `last_active` | datetime | Most recent event timestamp |
| `is_cold_start` | bool | True if `total_events < 3` → fall back to popularity ranking |

### `userBehaviorEvents.csv`
One row per view/apply event for authenticated users.

| Column | Type | Description |
|--------|------|-------------|
| `talentNo` | int | User primary key |
| `event_type` | str | `view` or `apply` |
| `job_id` | int | Job listing ID |
| `event_time` | datetime | Event timestamp |
| `job_city` | str | City (joined from 職缺.csv) |
| `job_category_mid` | str | Job mid-category (joined from 職缺.csv) |

### `job_skills_cache.csv`
Skills extracted per job listing (structured + optional LLM). Used by `graph_builder` to create REQUIRES edges.

### `graph_cache.pkl`
Serialised NetworkX DiGraph. Rebuilt by `graph_builder.build_graph()`. Contains User, Job, Skill, City, Category vertices and VIEWED, APPLIED, REQUIRES, LOCATED_IN edges.

## Conventions

- `talentNo = 0` means anonymous/unauthenticated user — never treat multiple rows with `talentNo = 0` as the same person. All derived user tables exclude `talentNo = 0`.
- Multi-value fields (`empStr`, `c0`, `d0`) are comma-separated strings and must be split before use.
- City and job-category codes in search logs are numeric; job listings (`職缺.csv`) already contain Chinese name strings — cross-reference by name when joining.
- All raw CSVs and derived CSVs are git-ignored (`dataset/*.csv`). Run the ETL scripts to regenerate them.
- Design decisions should be documented in `設計文件/` before implementation; the current authoritative design reference is `draft3rewrite.md`.
- Tests live in `src/tests/` (integration) and `src/utils/` (unit). Run with `pytest`.
- The API server entrypoint is `app.py` (FastAPI), not `main.py`.
